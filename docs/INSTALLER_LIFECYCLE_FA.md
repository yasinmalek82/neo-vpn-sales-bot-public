# Update و Uninstall

همان لینک ثابت، نسخهٔ تأییدشدهٔ فعلی را دریافت می‌کند. منو کاملاً انگلیسی است:

- `1 Install`: نصب تازه؛ نصب موجود را بازنویسی نمی‌کند.
- `2 Status`، `3 Start`، `4 Stop`.
- `5 Update`: ارتقای برنامه با حفظ تنظیمات و داده‌ها.
- `6 Uninstall`: حذف برنامه با انتخاب روش نگه‌داری داده.
- `0 Exit`.

## Update

پس از پیکربندی اولیه، توکن ربات، پنل، ادمین‌ها، کارت و کلید SMS دوباره پرسیده نمی‌شوند. تنظیمات فعال از Compose خوانده و بدون چاپ رازها حفظ می‌شوند؛ فایل خصوصی Shortcut نیز با همان کلید نگه داشته می‌شود. فایل‌های `source/config` و volumeهای موجود حفظ می‌شوند.

قبل از تغییر، نسخه و imageهای نصب فعلی، مالکیت volumeها و اتصال Docker محلی بررسی می‌شوند. پیکربندی نسخهٔ جدید پیش از توقف برنامه اعتبارسنجی می‌شود. سپس bot و Caddy متوقف و بکاپ خصوصی ساخته می‌شود:

- مسیر پیش‌فرض: `/opt/neo-test-backups/backup-*`، با دسترسی خصوصی.
- `installation/`: نسخهٔ کامل تنظیمات و فایل‌های قبلی، شامل فایل‌های خصوصی.
- `database.pgdump`: در صورت وجود دیتابیس؛ آرشیو کامل PostgreSQL، با بررسی قابل‌خواندن‌بودن محتوای آن.
- آرشیو volumeهای دیگر، از جمله فایل‌های برنامه، بکاپ‌ها و دادهٔ Caddy.
- `backup.json`: وضعیت `ready` و SHA256 فایل‌های بکاپ. `preparing` یعنی بکاپ کامل نشده است.

حفظ همان password دیتابیس و همان volumeها الزامی است. imageهای PostgreSQL و Caddy در Update ربات به‌صورت خودکار ارتقا نمی‌یابند؛ نسخهٔ واقعی آن‌ها در manifest نصب باقی می‌ماند.

اگر bot فعال بوده، پس از آپدیت شروع می‌شود. اگر فعال نبوده، شروع نسخهٔ جدید جداگانه پرسیده می‌شود. migrationهای نسخهٔ جدید ممکن است هنگام startup اجرا شوند. در شکست startup، bot متوقف می‌شود؛ دیتابیس خودکار restore نمی‌شود تا پرداخت یا تغییر تازه‌ای از بین نرود. ابتدا Status و بکاپ را بررسی کن و بازیابی را با توجه به schema و رویدادهای جدید انجام بده.

روی نصب جدید، این فرمان نیز همیشه راه‌انداز تأییدشدهٔ فعلی را می‌گیرد:

```bash
sudo sh /opt/neo-test/install.sh update
```

برای نسخه‌های قدیمی که هنوز فرمان update ندارند، لینک ثابت را اجرا و `5 Update` را انتخاب کن. نسخهٔ اولیهٔ `04a358f7f7a7` در مسیر استاندارد `/opt/neo-test` قابل شناسایی است. کپی‌ها، پوشه‌های بکاپ، پروژه‌های Docker دیگر، دیتابیس خارجی و mountهای سفارشی خودکار تغییر نمی‌کنند.

## Uninstall

حالت `1`، containerهای برنامه را حذف می‌کند و دیتابیس، volumeها و تنظیمات را نگه می‌دارد. برای اجرای دوباره Start یا برای نسخهٔ جدید Update را انتخاب کن.

حالت `2`، پس از بکاپ، داده‌های فعال همان پروژه را حذف می‌کند؛ باید عبارت دقیق `DELETE neo-test DATA` را تایپ کنی. حذف فقط برای volumeهای دارای مالکیت `neo-test` انجام می‌شود و بدون force است. بکاپ خصوصی خارج از پوشهٔ نصب باقی می‌ماند. این حالت تاریخچهٔ کیف پول، سفارش، پرداخت و رزرو مبلغ SMS را از دیتابیس فعال حذف می‌کند؛ پیش از شروع بانک بلو روی دیتابیس تازه، واریزهای معوق قبلی را تطبیق بده.

Docker، swap، imageها، cache دانلود و پروژه‌های دیگر حذف نمی‌شوند. بکاپ‌ها خودکار پاک نمی‌شوند؛ فضای دیسک و انتقال امن نسخه‌های قدیمی را مدیریت کن.

این قابلیت در این مرحله روی سرور واقعی مالک اجرا نشده است؛ طبق درخواست مالک مجموعهٔ آزمون تازه اجرا نشده است. مبانی خواندن پیکربندی و تولید آرشیو با [Docker Compose config](https://docs.docker.com/reference/cli/docker/compose/config/) و [PostgreSQL pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html) تطبیق داده شده است.
