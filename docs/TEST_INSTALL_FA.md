# نصب آزمایشی NEO با تأیید پیامک بلو

این بسته snapshot نسخهٔ فعلی برای آزمایش نصب و پرداخت است؛ انتشار production یا انتقال مشتریان میرزا نیست.
نسخهٔ بسته از commit مشخص ساخته شده، همهٔ imageها `linux/amd64` و داخل آرشیو هستند و SHA256 بررسی می‌شود.
نصب‌کننده از imageهای جدید روی سرور build نمی‌گیرد و به Docker Hub برای دریافت image برنامه نیاز ندارد.

## سرور لازم

- Ubuntu 22.04 یا 24.04 با معماری amd64، Python 3 و دسترسی root/sudo.
- برای این آزمایش 2 GB RAM و 5 GB فضای خالی پیشنهاد می‌شود؛ نصب‌کننده گزینهٔ swap اختیاری هم دارد.
- یک زیردامنه با رکورد مستقیم A به IP همین سرور. رکورد AAAA اشتباه و پراکسی DNS را برای تست اولیه اصلاح/خاموش کن.
- پورت‌های 80، 443 و 8080 باید آزاد باشند. نصب‌کننده سرویس دیگری را متوقف نمی‌کند.
  تنها 80 و 443 عمومی می‌شوند؛ PostgreSQL و پورت داخلی برنامه عمومی نیستند.
- توکن یک ربات تستی که هم‌زمان در جای دیگری polling نمی‌کند، شناسهٔ عددی ادمین،
  آدرس HTTPS و API key پنل تست، شمارهٔ کارت مقصد بلو و نام صاحب کارت را آماده داشته باش.
- اینترنت برای GitHub، نصب Docker در صورت نیاز، تلگرام، پنل و دریافت گواهی HTTPS لازم است.

## یک دستور روی سرور

مخزن و بسته عمومی‌اند و برای دانلود به حساب یا توکن GitHub نیاز نداری.
کلیدهای ربات و پنل را فقط هنگام نصب روی سرور وارد کن.

```bash
curl -fsSL https://raw.githubusercontent.com/yasinmalek82/neo-vpn-sales-bot-public/main/setup.sh | sudo sh
```

فایل شروع نصب، نسخهٔ تأییدشدهٔ `test/installer-04a358f7f7a7` را انتخاب می‌کند.
فرمان را در ترمینال SSH اجرا کن تا سؤال‌های نصب را ببینی. در اجرای pipe،
ورودی نصب‌کننده از `/dev/tty` گرفته می‌شود.

این دستور همان تگ ثابت را دریافت می‌کند، فایل بسته و checksum را از همان Release می‌گیرد،
checksum و مسیرهای آرشیو را بررسی می‌کند و نصب‌کننده را اجرا می‌کند. فایل ورودی روی `main` است،
اما دانلودکننده و بسته از تگ ثابت بالا گرفته می‌شوند؛ نسخه به‌صورت خودکار از `latest` انتخاب نمی‌شود.
در انتخاب «Enable automatic Blu SMS confirmation» گزینهٔ `y` یا Enter را بزن.
نصب‌کننده یک کلید تصادفی مستقل برای آیفون می‌سازد و تنظیمات را با دسترسی خصوصی ذخیره می‌کند.
شروع سرویس‌ها در پایان سؤال جداگانه دارد. مسیر پیش‌فرض `/opt/neo-test` و پروژهٔ Compose `neo-test` است.
نصب روی پوشه یا پروژهٔ موجود را بدون بازنویسی متوقف می‌کند؛ این بسته ابزار ارتقای نصب قبلی نیست.

### swap اختیاری

نصب‌کننده RAM و swap موجود را نشان می‌دهد. اگر swap موجود باشد، آن را حفظ می‌کند و
swap دیگری نمی‌سازد. اگر swap نداشته باشی، در اجرای تعاملی برای ساخت `1 GiB` سؤال می‌پرسد؛
Enter یا `n` یعنی هیچ تغییری نده. فقط `y` یا `yes` اجازهٔ ساخت است.
عدد `1 GiB` پیشنهاد شروع است و ظرفیت برای 50–100 کاربر یا هر بار مشخصی را تضمین نمی‌کند.

در اجرای بدون ترمینال، ساخت پیش‌فرض ممنوع است؛ فقط گزینهٔ صریح `--swap-1g` آن را مجاز می‌کند.
`--no-swap` سؤال را هم رد می‌کند. این گزینه‌ها را می‌توان به `install.sh` یا دانلودکننده داد.
فایل اختصاصی `/neo-test.swap` روی ext4/xfs با دسترسی `0600`، تخصیص واقعی فضا،
`mkswap` و `swapon` ساخته و یک‌بار در `/etc/fstab` ثبت می‌شود. علاوه بر حجم فایل،
`256 MiB` فضای خالی ذخیره لازم است. فایل/تنظیم قبلی یا فایل‌سیستم پشتیبانی‌نشده دست‌کاری نمی‌شود.
در خطای ساخت، فقط فایل و خط fstab همین اجرا پاک می‌شود؛ اگر خاموش‌کردن swap جدید ممکن نباشد،
فایل فعال برای بررسی نگه داشته می‌شود. swapی که با موفقیت ساخته شده، با توقف ربات حذف نمی‌شود.

## روش فایل آفلاین

اگر دانلود GitHub از سرور مقدور نیست، دو asset `BUNDLE_NAME.tar.gz` و
`BUNDLE_NAME.tar.gz.sha256` را در مرورگر دانلود و روی سرور منتقل کن:

```bash
sha256sum -c BUNDLE_NAME.tar.gz.sha256
tar -xzf BUNDLE_NAME.tar.gz
cd BUNDLE_NAME
sudo sh install.sh
```

## تنظیم آیفون

فایل `NEO-Blu-Payment.shortcut` را از assetهای همین Release به آیفون اضافه کن.
روی سرور با دستور زیر مقادیر خصوصی اتصال را فقط برای خودت ببین:

```bash
sudo cat /opt/neo-test/shortcut-settings.json
```

در Shortcut، URL را از فیلد `url` و header `Authorization` را برابر `Bearer TOKEN`
با مقدار `token` همین فایل قرار بده. `sender` در هر دو طرف `BLUE` است.
اتومیشن Message باید فقط مخاطب واقعی بانک که با نام `BLUE` ذخیره کرده‌ای را انتخاب کند،
عبارت «واریز پول» را فیلتر کند و متن کامل پیامک را به Shortcut بدهد.
اجرای بدون تأیید و هنگام قفل بودن را روی همان آیفون آزمایش کن.
راهنمای بیشتر: `source/docs/BANK_SMS_BLU.md` و فایل اصلی در پوشهٔ `source/docs/shortcuts/`.

## آزمایش واقعی پس از نصب

1. از ربات تستی `/start` و از ادمین `/admin` بزن؛ اتصال پنل و گروه‌های فروشگاه را تنظیم کن.
2. یک پلن آزمایشی با مبلغ کم و گروه پنل مشخص بساز. با مشتری تستی سفارش ثبت کن.
3. مبلغ فاکتور شامل خرده‌مبلغ است؛ دقیقاً همان مبلغ را با اجازهٔ صاحب حساب واریز کن.
4. دریافت پیامک روی آیفون، نتیجهٔ درخواست و سپس تحویل یک کارت سرویس را بررسی کن.
   فعال‌سازی از کارگر بازیابی می‌آید و ممکن است تا نوبت بعدی آن زمان ببرد.
5. همان پیامک را دوباره به Shortcut بده؛ نتیجه باید `duplicate` باشد و اعتبار یا سرویس دوم ساخته نشود.
   سفارش منقضی، مبلغ اشتباه و قطع اینترنت باید بررسی دستی بخواهند.

خرده‌مبلغ یک‌بار به کیف پول مشتری برمی‌گردد و قیمت پایهٔ سرویس تغییر نمی‌کند.
مبالغ رزروشده برای حساب دوباره استفاده نمی‌شوند؛ پس از پرشدن ظرفیت، رسید دستی ادامه پیدا می‌کند.
این روش استعلام بانک نیست؛ حساب مقصد و آیفون باید درست به هم متصل باشند.
برای آزمایش، حساب/کارت و سفارش‌های تست را با پرداخت‌های هم‌زمان ربات دیگری مخلوط نکن.

## وضعیت و توقف

```bash
cd /opt/neo-test
sudo sh install.sh status
sudo sh install.sh stop
sudo sh install.sh start
```

داده‌ها در volumeهای همین پروژه می‌مانند؛ نصب‌کننده `down -v` اجرا نمی‌کند.
اطلاعات مهم یا مشتریان واقعی را بدون بکاپ و بررسی readiness وارد این نصب آزمایشی نکن.
«healthy» اثبات دریافت پیامک روی آیفون، تحویل VPN یا آماده‌بودن برای مشتری واقعی نیست.
